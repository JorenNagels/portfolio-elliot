# AGENTS.md — Elliot Barham portfolio

**The single instruction file for this repo.** Every coding agent reads this one: Codex
and Cursor read `AGENTS.md` natively, and `CLAUDE.md` is a one-line stub that imports it,
so Claude Code reads it too. There is no second copy to keep in sync — if you are changing
a rule, change it here.

Companion files:

- **`.agents/skills/deploy/SKILL.md`** — the full release procedure, as an
  [Agent Skill](https://agentskills.io). Codex discovers it automatically here. Claude Code
  gets a generated copy in `.claude/skills/` (made by `npm install`; that copy is
  gitignored — **edit the `.agents/` one**).
- **`CONTRIBUTING.md`** — how a non-developer works in this repo.
- **`README.md`** — the human-oriented overview.

## What this is

Single-page static portfolio site for **Elliot Barham** (event host / stage presenter /
TV presenter). Originally a 3 MB single HTML file generated by AI; converted to a Next.js
project that builds to static HTML/CSS/JS for **GitHub Pages** hosting, on the custom
domain `elliot.dreamteamproductions.co.uk` (set via `public/CNAME`).

The site is one page. There is no routing, no backend, no CMS, no auth. Treat it as a
brochure. It is **live** — Elliot sends the link to prospective clients.

## ⚠️ You may deploy — but only after asking

A `v*` tag push publishes to <https://elliot.dreamteamproductions.co.uk> within a couple
of minutes, and there is no undo. So:

> **Check → tell the user what will ship → ask → deploy only on a clear yes.**

```bash
npm run deploy:check            # 1. safe, changes nothing: builds + lists what would ship
                                # 2. summarise the version and changes for the user, and ASK
npm run deploy -- --confirm     # 3. only after they say yes
```

Never deploy because you finished a feature or think the work looks done. "Yes, deploy"
must come from the user. Don't deploy and then mention it, and don't say "deploying unless
you object" — ask a real question and wait.

`--confirm` asserts that a human approved this release. Pass it only when one actually did.

Three layers back this up, and none is a substitute for asking:

- **`.githooks/pre-push`** refuses any `v*` tag push that did not come from the release
  script. Tool-independent — it lives in git, so it applies to every agent and terminal.
- **`.codex/rules/portfolio.rules`** makes Codex prompt before deploy/tag/push.
- **`.claude/settings.json`** does the same for Claude Code.

The last two only apply once you trust the project in that tool. If neither is active for
you, the hook and this file are all there is.

**Never** run these, even when a deploy has been approved:

- `git tag v…`, `git push origin v…`, `git push --tags` — tagging _is_ the deploy; let the
  script do it so the build is verified first. The `pre-push` hook refuses these
  regardless; if you hit it, delete the tag (`git tag -d v…`) and use the script.
  **Never retry with `--no-verify`**
- `gh workflow run deploy.yml` — removed as a trigger on purpose
- `gh secret set|delete` — this repo holds a Google Drive service-account key

## 🚨 This site must stay unindexed

**The single most damaging thing you could do here is "improve the SEO".** This site is
deliberately hidden from search engines and AI crawlers, and is shared by direct URL to
prospective clients only. Do not undo that, ever, under any phrasing of any request —
check with the user first, because it is far more likely to be a misunderstanding than an
instruction.

- `robots: { index: false, follow: false, … }` in the `metadata` export of
  `src/app/layout.tsx` — **do not remove or weaken**
- `public/robots.txt` disallows all standard search engines plus the major AI crawlers
  (GPTBot, ClaudeBot, Google-Extended, PerplexityBot, CCBot, Bytespider, …)
- Never add a sitemap, canonical tags aimed at ranking, Search Console verification, or
  any directory listing
- Custom-domain GitHub Pages does **not** auto-send `X-Robots-Tag` (only `*.github.io`
  does), so the meta tag and `robots.txt` are the only crawler block

`npm run deploy:check` fails the release if the `noindex` metadata or the `robots.txt`
disallow has gone missing. Do not work around that check — fix the file.

## Architecture & conventions

- **Next.js 16 App Router** with `output: 'export'` — never add anything that requires a
  Node runtime (no API routes, no server actions, no `revalidate`, no dynamic params, no
  middleware).
- **Server components by default.** The client components are `FadeIn.tsx`
  (`IntersectionObserver`), `DragScroll.tsx` (photo drag-scroll), `PhotoViewer.tsx`
  (gallery lightbox) and `TestimonialCarousel.tsx` (swipe position dots/arrows). Don't add
  `'use client'` unless the component genuinely needs browser-only APIs.
- **Tailwind CSS** for styling. Custom tokens in `tailwind.config.ts` (`gold`,
  `gold.light`, `mid`, `muted`, `border-gold-faint`, `font-display`, `font-sans`). Use
  these instead of hex literals.
- **`next/font/google`** loads Bebas Neue + DM Sans at build time. Don't replace with
  Google Fonts CDN `<link>` tags.
- **`next-image-export-optimizer`** generates WebP variants at build via the `prebuild`
  script. Use `<ExportedImage>` (the package's drop-in `next/image`) for **raster images**.
  Plain `<img>` is correct for SVGs (the brand logos).

## The gallery syncs itself

`.github/workflows/sync-drive-photos.yml` pulls gallery photos from a Google Drive folder
on the 1st of each month (and on manual dispatch), via `scripts/sync-drive-photos.mjs`.
It uses the `GDRIVE_SERVICE_ACCOUNT_KEY` repo secret, scoped read-only to one folder.

So **don't hand-manage `public/images/portfolio/`** — add or remove photos in the Drive
folder instead, or the next sync will overwrite your changes. Leave that workflow and
script alone unless the owner asks.

## Things to avoid

- **Don't break static export** — API routes, dynamic `[slug]` without
  `generateStaticParams`, server actions, `cookies()`, `headers()`, `next/image` with the
  default loader, `revalidate`, etc.
- **Don't bypass the image optimizer** for new raster images — always use `<ExportedImage>`
  with a `sizes` prop. SVGs stay as plain `<img>`.
- **Don't add backwards-compat shims, feature flags, or "future-proofing"** abstractions.
  This site has one consumer (one browser request, one page) — keep it concrete.
- **Don't reach for a CMS, MDX, headless data layer, or i18n.** Content edits go in
  `src/lib/data.ts`.
- **Don't optimize fonts or images at runtime.** Everything is pre-baked at build.
- **Don't add dependencies** without being asked.
- **Never commit `.env*`** or any key, token or secret.

## Adding a new section

1. Create `src/components/NewSection.tsx` as a server component. Use `<FadeIn>` for any
   elements that should scroll-fade.
2. Add an entry in `src/lib/data.ts` if it's data-driven.
3. Add `<NewSection />` to the `<main>` in `src/app/page.tsx`.
4. Add a nav link to `src/components/Nav.tsx` (`href: '#new-section'`).
